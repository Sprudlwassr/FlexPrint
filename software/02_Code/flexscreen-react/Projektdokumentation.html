Projekt: flexscreen-react  |  Stand: April 2026  |  Autor: Samir El-Farfar

Diese Dokumentation erklärt den vollständigen Quellcode des FlexScreen-Projekts. Nach dem Lesen verstehst du, wie jede Datei funktioniert, warum bestimmte Entscheidungen getroffen wurden und wie die einzelnen Teile zusammenspielen.

1. Was ist FlexScreen?

FlexScreen ist eine React-basierte Touchscreen-Benutzeroberfläche zur Steuerung eines 3D-Druckers. Sie läuft auf einem Raspberry Pi 5 mit einem angeschlossenen 800×480px-Touchscreen und kommuniziert mit Klipper (3D-Drucker-Firmware) über die Moonraker-API.

Was kann die App?

  • Verbindungsstatus zu Moonraker und Klipper anzeigen
  • Echtzeittemperaturen (Extruder, Heizbett, Raspberry Pi) im Header anzeigen
  • Temperaturziele für Extruder und Heizbett setzen
  • Achsen des Druckers bewegen (X, Y, Z – Homing)
  • Druckdateien auswählen
  • Aktuellen Druckauftrag überwachen (Fortschritt, Layer, Zeiten)
  • G-Code direkt über eine Konsole an den Drucker senden
  • Z-Offset konfigurieren

3. Wie React funktioniert (Grundlagen)

Bevor wir den Code erklären, kurz die wichtigsten React-Konzepte die im Projekt genutzt werden:

Komponenten

Jede Datei mit .jsx exportiert eine Komponente – eine JavaScript-Funktion, die HTML-ähnlichen Code (JSX) zurückgibt. Beispiel:

const Button = ({ label }) => (
  <button>{label}</button>
);

useState – lokaler Zustand

Mit useState merkt sich eine Komponente Werte zwischen Renders. Ändert sich der State, rendert React die Komponente neu.

const [count, setCount] = useState(0);
// count = aktueller Wert, setCount = Funktion zum Ändern

useEffect – Nebeneffekte

Führt Code aus, wenn die Komponente geladen wird oder sich bestimmte Werte ändern. Häufig für Timer, API-Calls oder Event-Listener.

useEffect(() => {
  const id = setInterval(() => console.log('tick'), 1000);
  return () => clearInterval(id); // Aufräumen beim Unmount
}, []); // [] = nur einmal beim Start

useRef – Referenz ohne Re-Render

Speichert Werte die sich ändern dürfen, ohne einen neuen Render auszulösen. Häufig für DOM-Elemente oder Timers.

Context (useContext)

Teilt Daten mit allen Komponenten im Baum, ohne Props durch alle Ebenen weiterzureichen. Im Projekt für den Moonraker-State genutzt.

4. Einstiegspunkte

4.1 index.html

Die einzige HTML-Datei des Projekts. Der Browser lädt sie zuerst.

<meta name="viewport" content="width=device-width, initial-scale=1.0,
      maximum-scale=1.0, user-scalable=no" />

user-scalable=no verhindert ungewolltes Zoomen auf dem Touchscreen. Das <div id="root"> ist der Anker, in den React die gesamte App rendert.

4.2 src/main.jsx

import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import './style.css'
import App from './App.jsx'

createRoot(document.getElementById('root')).render(
  <StrictMode><App /></StrictMode>
)

createRoot verbindet React mit dem #root-Element. StrictMode aktiviert zusätzliche Entwicklungswarnungen (z.B. bei unsauberem useEffect). Die style.css wird hier global importiert – gilt für die gesamte App.

4.3 src/config.js

export const MOONRAKER_CONFIG = {
  IP:   '192.168.1.42', // ← Pi-IP-Adresse hier eintragen
  PORT: 7125,
  get WS_URL()   { return `ws://${this.IP}:${this.PORT}/websocket`; },
  get HTTP_URL() { return `http://${this.IP}:${this.PORT}`; },
};

Zentrale Konfigurationsdatei. Die IP-Adresse muss auf die des Raspberry Pi geändert werden. Die get-Syntax erstellt berechnete Eigenschaften – WS_URL wird jedes Mal neu zusammengebaut wenn sie gelesen wird. Port 7125 ist der Moonraker-Standard.

5. App.jsx – Das Herzstück

Diese Datei enthält zwei Komponenten: App und Layout.

5.1 App-Komponente

function App() {
  const [time, setTime] = useState('');

  useEffect(() => {
    const update = () => {
      const now = new Date();
      setTime(now.toLocaleTimeString('de-DE', { hour: '2-digit', minute: '2-digit' }));
    };
    update();
    const interval = setInterval(update, 1000);
    return () => clearInterval(interval);
  }, []);

  return (
    <BrowserRouter>
      <MoonrakerProvider>
        <Routes>
          <Route path="/" element={<StartScreen />} />
          <Route path="*" element={<Layout time={time} />} />
        </Routes>
      </MoonrakerProvider>
    </BrowserRouter>
  );
}

Was passiert hier:

  • Live-Uhr: setInterval aktualisiert die Uhrzeit jede Sekunde. Das return () => clearInterval räumt auf, wenn die Komponente entfernt wird (Speicherleck-Vermeidung).
  • BrowserRouter: Ermöglicht URL-basierte Navigation. Muss ganz außen sein, damit alle Kinder-Komponenten navigieren können.
  • MoonrakerProvider: Stellt die WebSocket-Verbindung und Drucker-Daten für alle Kind-Komponenten bereit.
  • Routes/Route: path="/" zeigt den StartScreen. path="*" fängt alle anderen URLs ab und zeigt das Layout mit Header/Footer.
  • time als Prop: Die Uhr wird in App berechnet und als Prop an Layout übergeben, weil useNavigate/useLocation innerhalb des Routers aufgerufen werden müssen.

5.2 Layout-Komponente

const START_PAGES = ['/dashboard', '/jobs', '/system'];

function Layout({ time }) {
  const navigate = useNavigate();
  const location = useLocation();
  const isStartPage = START_PAGES.includes(location.pathname);
  const { temps } = useMoonraker();

  return (
    <div className="main">
      <div className="header">
        <div className="headerLeft">
          {isStartPage
            ? <Link to="/" className="headerStartBtn">Start</Link>
            : <button className="headerBackBtn" onClick={() => navigate(-1)}>Back</button>
          }
        </div>
        <div className="headerCenter">
          <Link to="/"><img src={logo} className="header-logo"/></Link>
        </div>
        <div className="headerRight">
          <div className="headerTemps">
            <span className="tempItem">🌡 {temps.extruder.toFixed(1)}°</span>
            <span className="tempItem">🛏 {temps.bed.toFixed(1)}°</span>
            <span className="tempItem">Pi: {temps.pi.toFixed(1)}°</span>
          </div>
          {time}
        </div>
      </div>
      ...Footer mit Dashboard/Job/System Links...
    </div>
  );
}

Warum ist Layout eine eigene Komponente?

useNavigate() und useLocation() dürfen nur innerhalb eines <BrowserRouter> aufgerufen werden. Da App selbst den Router rendert, muss die Nutzung dieser Hooks in einer Kind-Komponente stattfinden – daher Layout.

Back vs. Start Button:

Auf Hauptseiten (Dashboard, Jobs, System) gibt es einen Start-Button, der zum Startbildschirm führt. Auf Unterseiten (Temperature, Print, Actions, Configuration) gibt es einen Back-Button der mit navigate(-1) zur vorherigen Seite zurückgeht – wie der Browser-Zurück-Button.

Echte Temperaturen:

const { temps } = useMoonraker() holt die Live-Temperaturen aus dem Moonraker-Context. .toFixed(1) rundet auf eine Nachkommastelle.

6. MoonrakerContext.jsx – Die API-Verbindung

Diese Datei ist das technische Herzstück der App. Sie verwaltet die WebSocket-Verbindung zu Moonraker und stellt alle Drucker-Daten für alle Komponenten bereit.

6.1 Was ist ein Context?

Ein React Context ist ein globaler Datenspeicher. Jede Komponente innerhalb des <MoonrakerProvider> kann mit useMoonraker() auf die Daten zugreifen – ohne Props weitergeben zu müssen.

6.2 Was ist WebSocket?

Im Gegensatz zu HTTP (Anfrage → Antwort → fertig) bleibt eine WebSocket-Verbindung dauerhaft offen. Moonraker sendet Temperatur-Updates, Status-Änderungen etc. automatisch sobald sie passieren. Kein Polling nötig.

6.3 JSON-RPC Protokoll

Moonraker spricht JSON-RPC über WebSocket. Das bedeutet: Befehle werden als JSON-Objekte gesendet:

// Senden:
{ "jsonrpc": "2.0", "method": "printer.info", "id": 1 }

// Antwort:
{ "jsonrpc": "2.0", "result": { "state": "ready", ... }, "id": 1 }

// Moonraker sendet automatisch Events:
{ "jsonrpc": "2.0", "method": "notify_status_update", "params": [...] }

6.4 Der Code im Detail

State-Variablen:

const [moonrakerConnected, setMoonrakerConnected] = useState(false);
const [klipperState, setKlipperState] = useState('disconnected');
const [temps, setTemps] = useState({ extruder: 0, bed: 0, pi: 0 });

send() – JSON-RPC Hilfsfunktion:

const send = useCallback((method, params = {}) => {
  return new Promise((resolve, reject) => {
    const id = msgId++;
    pendingRequests.current[id] = { resolve, reject };
    ws.current.send(JSON.stringify({ jsonrpc: '2.0', method, params, id }));
  });
}, []);

Jede Anfrage bekommt eine eindeutige id. Die Antwort von Moonraker enthält dieselbe id, damit wir wissen welche Anfrage beantwortet wird. Das Promise wird aufgelöst sobald die Antwort eintrifft.

connect() – Verbindungsaufbau:

  1. WebSocket-Verbindung herstellen
  2. Bei onopen: printer.info abfragen (Klipper-Status), dann Temperatur-Updates abonnieren
  3. Bei onmessage: Antworten verarbeiten – entweder ausstehende Requests auflösen oder Events (notify_*) verarbeiten
  4. Bei onclose/onerror: Status auf disconnected setzen und nach 3 Sekunden neu verbinden

Abonnieren von Live-Updates:

await send('printer.objects.subscribe', {
  objects: {
    extruder:   ['temperature', 'target'],
    heater_bed: ['temperature', 'target'],
    'temperature_sensor raspberry_pi': ['temperature'],
  },
});

Danach schickt Moonraker bei jeder Temperaturänderung ein notify_status_update-Event. Der Sensor-Name 'temperature_sensor raspberry_pi' muss in Anführungszeichen stehen weil er ein Leerzeichen enthält.

Bereitgestellte Werte:

WertTypBeschreibung
moonrakerConnectedbooleanIst die WebSocket-Verbindung aktiv?
klipperStatestring'ready', 'disconnected', 'shutdown', 'error'
klipperReadybooleanKurzform: klipperState === 'ready'
tempsobject{ extruder, bed, pi } als Zahlen in °C
sendGcodefunctionG-Code-Befehl an Drucker senden

2. Druckerstatus-Karten (dashLeft):

Zwei Karten links: Druckerstatus (Status-Badge, Dateiname, Layer, Temps, Z-Position) und Fortschritt (Fortschrittsbalken + Zeiten). Daten kommen aktuell aus dem hartkodiertem job-Objekt – werden später von der API befüllt.

3. G-Code Konsole:

const send = async () => {
  const cmd = input.trim();
  if (!cmd || sending) return;
  setInput('');
  setLog(prev => [...prev, { type: 'send', text: `> ${cmd}` }]);
  setSending(true);
  try {
    await sendGcode(cmd);                                    // echter API-Call
    setLog(prev => [...prev, { type: 'recv', text: 'ok' }]);
  } catch (err) {
    setLog(prev => [...prev, { type: 'error', text: `!! ${err.message}` }]);
  } finally {
    setSending(false);
  }
};

sendGcode kommt aus dem MoonrakerContext und sendet den Befehl per WebSocket. Während des Sendens zeigt der Button … und ist deaktiviert. Fehler erscheinen rot im Log.

Das logEndRef sorgt dafür, dass das Log automatisch nach unten scrollt wenn neue Einträge kommen:

useEffect(() => {
  logEndRef.current?.scrollIntoView({ behavior: 'smooth' });
}, [log]);

7.3 TemperatureScreen.jsx

Zwei Karten nebeneinander: Toolhead (Extruder) und Heated Bed.

Wichtig – zwei State-Variablen pro Karte:

const [target, setTarget] = useState(defaultTarget); // gesetzter Wert (Anzeige)
const [input, setInput] = useState(defaultTarget);    // Puffer (Eingabe)

Der angezeigte Zielwert (target) ändert sich erst beim Klick auf Setzen. Die Eingabe (input) kann frei verändert werden ohne sofort zu wirken. apply() kopiert dann input → target.

+/− Buttons:

const adjust = (delta) => setInput(prev => Math.max(0, prev + delta));

Math.max(0, ...) verhindert negative Temperaturen.

7.4 PrintScreen.jsx

Sortierbare Dateiliste. Daten kommen aus dem mockFiles-Array (Platzhalterdaten – später von Moonraker).

Sortierung:

const sorted = [...mockFiles].sort((a, b) => {
  if (sortBy === 'name') return a.name.localeCompare(b.name);
  // ...nach Datum
});

[...mockFiles] erstellt eine Kopie des Arrays (wichtig! direktes Sortieren würde den Original-Array verändern). localeCompare sortiert Strings sprachsensitiv (Umlaute etc.).

Dateitypen:

Ordner zeigen nur Name + Datum. STL-Dateien zeigen Upload-Datum, Größe, Druckzeit und einen Druck-Button.

7.6 JobScreen.jsx

Zeigt den laufenden Druckauftrag. Daten kommen aktuell aus dem hartkodiertem job-Objekt.

CircularProgress – SVG-Kreis:

const r = 44;
const circ = 2 * Math.PI * r;           // Gesamtumfang des Kreises
const offset = circ - (value/100)*circ; // nicht ausgefüllter Teil

Der Fortschrittskreis wird mit stroke-dasharray (Gesamtumfang) und stroke-dashoffset (fehlender Teil) gezeichnet. transform="rotate(-90)" startet den Kreis oben statt rechts.

Action-Buttons:

Pause, Cancel, Fine Tuning, Settings – jeweils mit farbigem Balken oben. Noch ohne API-Funktion (onClick={() => {}}).

7.7 ConfigurationScreen.jsx

Z-Offset einstellen (Abstand Düse zu Druckbett).

Drei State-Variablen:

const [offset, setOffset] = useState(-0.10);   // aktuell angezeigter Wert
const [input, setInput] = useState('-0.10');    // Texteingabe (String!)
const [applied, setApplied] = useState(-0.10); // zuletzt gesetzter Wert

input ist ein String, damit der Nutzer auch Zwischenzustände wie "-0." tippen kann ohne Fehler. Beim Setzen wird er mit parseFloat() in eine Zahl umgewandelt. isNaN() fängt ungültige Eingaben ab.

Schrittweiten:

const STEPS = [0.01, 0.05, 0.1, 0.5];
{[1, -1].map(sign => (
  <div className="tempCardControls">
    {STEPS.map(step => (

Durch das Mapping über [1, -1] werden beide Zeilen (positive und negative Schritte) mit einer Schleife erzeugt statt 8 Buttons einzeln zu schreiben.

Verschachtelte Routes

Die inneren Routes (in Layout) sind in einen äußeren path="*"-Route eingebettet. Das bedeutet: Layout rendert immer Header und Footer, und der innere Router tauscht nur den Inhalt aus.

Warum zwei Router? Der äußere Router in App.jsx wechselt zwischen StartScreen (kein Header/Footer) und Layout (mit Header/Footer). Der innere Router in Layout wechselt zwischen den einzelnen Seiten innerhalb des Layouts.

9.5 display800x480.css – Touchscreen-Anpassungen

Wird nur aktiv wenn: max-height: 500px AND orientation: landscape

Hauptproblem: Bei 480px Höhe ist 1vh = 4.8px. Werte unter 2.5vh werden kleiner als 12px (unlesbar).

Lösung: clamp(minimum, vh-Wert, maximum) setzt eine Untergrenze:

/* Ohne clamp: 1.7vh bei 480px = 8.2px (zu klein!) */
.jobStatusBadge { font-size: 1.7vh; }

/* Mit clamp: mindestens 10px, vh-basiert, max 14px */
.jobStatusBadge { font-size: clamp(10px, 1.7vh, 14px); }

Zusätzlich: touch-action: manipulation auf allen interaktiven Elementen entfernt die 300ms Tap-Verzögerung auf Touch-Geräten.

10. api/moonrakerApi.jsx – HTTP-Referenz

Diese Datei enthält HTTP-Hilfsfunktionen. Sie ist noch nicht in die UI eingebunden – sie dient als Referenz und wird später für Aktionen genutzt, die kein Live-Update brauchen.

FunktionMoonraker-EndpointZweck
emergencyStop()POST /printer/emergency_stopSofortiger Not-Aus
restartFirmware()POST /printer/firmware_restartKlipper neu starten
sendGcode(script)POST /printer/gcode/scriptG-Code senden (HTTP)
setTemperature(heater, temp)POST /printer/gcode/scriptTemperatur setzen
controlPrint(action)POST /printer/print/{action}pause/resume/cancel
WebSocket vs. HTTP: Im MoonrakerContext wird G-Code über WebSocket gesendet (schneller, gleiche Verbindung). Die HTTP-Funktionen in moonrakerApi.jsx sind für einmalige Aktionen gedacht die keine offene Verbindung brauchen.

13. Projekt starten & deployen

Entwicklung (Laptop):

npm run dev

Öffnet den Dev-Server auf http://localhost:5173. Änderungen erscheinen sofort (Hot Module Replacement).

Auf dem Raspberry Pi:

# Projekt kopieren (einmalig vom Laptop):
scp -r "/pfad/zum/projekt" pi@192.168.1.42:~/flexscreen-react

# Auf dem Pi:
cd ~/flexscreen-react
npm install
npm run dev -- --host   # --host macht den Server im Netzwerk erreichbar

Kiosk-Modus (Pi-Display):

chromium-browser --kiosk --noerrdialogs http://localhost:5173

Produktions-Build:

npm run build          # erstellt optimierte Dateien in dist/
npm run preview        # Vorschau des Build-Ergebnisses
